# Auth & AuthGuard 가이드

이 문서는 **인증 상태 관리(`useAuth`)와 라우트 가드(`AuthGuard`)를 어떻게 사용하는지**를 요약합니다.  
자세한 용어 정의는 `docs/FRONTEND_GLOSSARY.md`의 관련 섹션을 참고하세요.

---

## 개념 요약

- **Auth (도메인 개념)**  
  - 로그인 여부, 현재 유저, 현재 역할(brand/showhost)을 표현하는 인증 컨텍스트입니다.
- **`useAuth` (커스텀 훅)**  
  - `AuthContext`를 사용해 인증 상태(`isLoggedIn`, `user`, `currentRole`, `isLoading`)와  
    `login`, `logout`, `signup`, `refreshUser`와 같은 액션을 제공합니다.
- **`AuthGuard` (라우트 가드 컴포넌트)**  
  - 라우트 단위로 로그인 필요 여부, 게스트 전용 여부, 허용 역할(brand/showhost)을 선언적으로 지정합니다.

---

## 언제 `useAuth` 를 쓸까?

- **인증이 필요한 화면**에서:
  - 현재 로그인 여부에 따라 다른 UI를 보여주고 싶을 때
  - 현재 유저 정보(이름, 역할 등)를 헤더/프로필 영역에 노출하고 싶을 때
- **버튼 액션**에서:
  - "로그아웃" 버튼을 눌렀을 때 `logout`을 호출
  - "로그인" 폼 전송 시 `login`을 호출

예시 (개념적인 형태):

```tsx
const MyPageHeader = () => {
  const { authState, logout } = useAuth();

  if (authState.isLoading) return <Spinner />;
  if (!authState.isLoggedIn) return <LoginCTA />;

  return (
    <header>
      <span>{authState.user?.name} 님</span>
      <button onClick={logout}>로그아웃</button>
    </header>
  );
};
```

---

## 언제 `AuthGuard` 를 쓸까?

- **로그인이 반드시 필요한 페이지**:
  - 예: `/mypage`, `/mypage/portfolios`, `/campaigns/register` 등
- **특정 역할만 들어올 수 있는 페이지**:
  - 브랜드 전용: 캠페인 등록, 브랜드 대시보드 등
  - 쇼호스트/모델 전용: 포트폴리오/모델 등록, 내 지원 내역 등

라우트 정의(의미만 표현한 예시):

```tsx
<Route
  path={ROUTE_PATHS.mypage.root}
  element={
    <AuthGuard requireAuth allowedRoles={['brand', 'showhost']}>
      <MyPage />
    </AuthGuard>
  }
/>
```

## 에이전트/개발 시 체크리스트

- 새 페이지를 추가할 때:
  - [ ] 이 페이지가 **로그인 필수인지** 확인한다.
  - [ ] 특정 역할(brand/showhost)만 접근해야 한다면 `allowedRoles`를 설정한다.
  - [ ] 권한이 없을 때 보여줄 메시지/리다이렉트 경로가 자연스러운지 한 번 더 생각한다.
- 인증 관련 로직을 수정할 때:
  - [ ] `useAuth`를 통해 처리할 수 있는지 먼저 검토하고, 개별 페이지에서 중복 로직을 만들지 않는다.
  - [ ] 도메인 타입(`User`, `UserRole`)과 프론트 표현(`currentRole`)이 서로 어긋나지 않는지 확인한다.
